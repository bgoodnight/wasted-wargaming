# Repository Instructions

Read `PROJECT_BRIEF.md` before making substantial changes.

- Preserve `CNAME` exactly; do not delete, rename, or overwrite it.
- Maintain GitHub Pages compatibility and use relative paths.
- Keep the initial site framework-free: plain HTML, CSS, and JavaScript with no package manager or build process.
- Build mobile-first and prioritize accessibility, including contrast, readable type, tap targets, keyboard access, meaningful alt text, and reduced-motion support.
- Keep event details in a separate data source such as `events.json`; do not duplicate them throughout the HTML.
- Use clearly labeled placeholders for unconfirmed content. Never invent event dates, schedules, prices, URLs, logos, photos, or other details.
- Do not expose secrets or browser-side API keys.
- Keep the code understandable to a nonprofessional developer working with Codex.
- Before substantial edits, inspect the repository and briefly explain the proposed implementation.
- After site changes, preview and verify desktop and mobile layouts, links, paths, accessibility, and browser errors.
- Do not commit or push unless the user explicitly approves it.
